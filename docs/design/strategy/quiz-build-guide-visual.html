Quiz build guide · templates × ROI × proof

Don’t design a quiz. Assemble one.

A good product quiz is a known flow template for the category, filled with a small set of evidence-backed features, and validated behind a holdout. The builder picks the template, ships the Tier-A features by default, and A/B-proves the rest. Two rules govern everything below.

The two governing rules

1 · Map length & gate to the category, don’t globally minimize. Gifting/durables stay short with the email gate deferred; formulation/subscription run long with the gate at the reveal. 2 · Every lift number — including yours — is only believable behind an A/B holdout. Plan to a credible 5–15% band, prove the rest, and never quote a vendor’s selection-biased “25×.”

B

What to ship vs what to prove

graded by strongest independent evidence
Ship by default · Tier A
  • One-click add + discount permalink + Shop Pay on resultBaymard: ~70% abandonment, ~35% friction upside
  • Curated 1–3 recommendationsIyengar/Lepper — pitch as cognitive-load, not “paradox”
  • Social proof (rating + count + verified-buyer)Spiegel: +270% at 5 reviews; peaks 4.0–4.7★
  • Progress bar + one-question-per-screenNN/g, Baymard — cheap, cuts abandonment
  • Save-results (soft gate) + segmented email flowsMcKinsey: 10–15% personalization lift
Independent evidence, low cost, close to the money.
A/B-prove first
  • Bundles / “complete the routine”Best AOV lever, but numbers are vendor — test your catalog
  • Endowed progress (bar >0%)Tier-A theory, loyalty-card context — A/B the offset
  • Auto-advance on selectControlled study: no sig. gain + a11y cost. Test, default OFF
  • AI review summaries / “why it fits you”Gate behind grounding — ungrounded = FTC exposure
  • Mystery discount · SMS flowsVendor-inflated; SMS = hard TCPA consent
Real upside, but evidence is biased or carries a tax.
Do not build
  • Fake / resetting countdown timersFTC Dark Patterns + EU Digital Fairness
  • False scarcityServer-enforced real expiry is fine; cosmetic is illegal
  • Non-redeemable “everyone-wins” wheelsThe prize shown must be real
Regulatory lines, not preferences.

Test roadmap · impact × testability
  1. Quiz vs no quiz (holdout, RPV) — kills the selection-bias myth
  2. Email gate: required vs optional vs post-result
  3. Quiz length — completion is high-frequency, testable
  4. Entry point / placement
  5. Rec logic A vs B — small effect, defer to sequential
Measure revenue-per-visitor, not completion (gameable), and analyze everyone assigned, not just quiz-takers — comparing takers to all traffic is the #1 error. If a clean test needs >8 weeks: test a bigger swing, use a higher-frequency proxy, or ship on priors + a 5% permanent holdout and call it a monitored bet, not a proven result.
D

Build guardrails the generator enforces

hard invariants — block the emit
≥1 product / path

Every reachable result resolves to a real product; empty-set fallback ladder defined. The top runtime guardrail.

Determinism

Same answers → same rec. Scoring is a pure function; randomize display order, never the outcome.

No dead questions

Every question must change ≥1 filter or score. No dead-ends, no unreachable paths.

No sliders

Scale questions render as 3–5 discrete labeled taps (Bosch 2019). Default to tap-cards on native radios.

MECE options

Mutually exclusive & exhaustive; no overlapping ranges; ≤7 as radios, 8+ → dropdown; no double-barreled.

Gate late, by category

At/just before the result — never screen one. At-result for diagnostic; deferred for fit/durables/gifting.

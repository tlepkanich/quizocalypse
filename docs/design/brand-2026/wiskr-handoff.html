01

How to read this

Start here — it changes what the rest of the document means.

This is a value swap, not a rename. The 99 --qz-* token names in the admin sheet today are the same 99 names after this change — only their values move. That is the whole reason this can ship incrementally instead of as a rewrite. Three tokens are genuinely new (--qz-rule-strong, --qz-phone-r, --qz-home-ground) and one is scheduled for removal (--qz-font-mono, 35 sites, still an open decision).

Every screen below is live CSS, not a screenshot. They are assembled from the same base.mjs that generates this document's own styles, so a rule described in section 03 and the pixels in section 15 are guaranteed to be the same rule. Where a screen is interactive — the device toggles, the explainer steppers, the composer — it actually works. Click it.
  • R1One accent, and it always means the same thing. Violet marks somewhere you can act. It is never decoration, never a category colour, never a second brand. Status colours (ok / warn / crit) are a separate axis and never substitute for it.
  • R2Contrast is measured, never asserted. Every pair in section 03 is computed from the token values at build time. If someone changes a value, the number moves with it.
  • R3Inside the builder, our colour stands down. The merchant is looking at their own brand; a violet selection ring beside their terracotta button is two brands arguing. The editor re-points the accent tokens at the ink ladder — components do not change, only tokens.
  • R4White is the page. Home is the one exception (--qz-home-ground). A fully tinted variant was built and rejected — see section 17.

03

Colour & contrast

One accent. Every ratio below is computed, not typed.

The palette is a violet accent over a neutral with a slight violet bias — a pure grey next to a violet accent reads as unconsidered, and the bias is what makes the neutrals look chosen. The accent is used as a fill and as a boundary, but only --qz-accent-ink is used as body text: the accent itself is 5.6:1 on white, which passes for large text and fails the 4.5:1 body minimum, so the darker step exists specifically for that.

04

Shape, space & depth

Squared, tight, and almost flat.

Radii are 4 / 6 / 8 and the pill is 6px — nothing in this system is a full pill, which is the single biggest reason it reads more grown-up than the current admin. Depth is two elevations and both are structural: --qz-e-1 for a resting card, --qz-e-2 for anything that floats above the page. Nothing else casts a shadow. The one deliberate exception is the Home composer, which takes a 14px radius and a real shadow because it is the one thing on that page you are meant to type into.

Radius

4px marks, 6px controls, 8px containers. One step per role.

Elevation

Resting, and floating. There is no third.

Rules

Hairline separates; strong bounds a control at 3:1.

What the count turned up

Five findings that are not colour choices, and that a swap done row-by-row would miss.

--qz-color-primary is referenced 31 times and never defined.

Every one of those sites falls back to a hardcoded literal — #5563de in two places, #111 in another. They will NOT move when the accent changes, so a swap that looks complete will leave 31 sites painting the old blue. Define it as an alias of --qz-accent and delete the fallbacks.

--qz-ink and --qz-ink-2 hold the same value today (#2E2740).

So the ladder is really four steps wearing five names, and any screen using ink-2 for “secondary” has no visible hierarchy. Either give ink-2 its own step or retire it — do not swap it blind.

--qz-cream is #FFFFFF, identical to --qz-paper; --qz-rule-2 and --qz-cream-2 are two names for the same near-white.

Three names for two surfaces. Collapsing them is a prerequisite for the surface ladder to mean anything.

Two tokens in the sheet today fail WCAG AA as body text.

--qz-ink-4 is 4.28:1 across 55 call sites and --qz-ok is 4.36:1 across 24 — both under the 4.5:1 minimum. --qz-warn (5.43:1) and --qz-crit (5.19:1) do pass, but with little headroom. The Quartz values clear all four. This is a correctness fix that happens to arrive with a visual one.

17 tokens are defined and never referenced.

--qz-stage, --qz-graphite, the four --qz-pal-*-wash entries, four spacing steps, two shadows, three z-indexes. Delete them rather than porting them.

One addition that is not cosmetic: a 3:1 boundary token. There is no such token in the sheet today, so control borders use --qz-rule — a hairline that fails WCAG §1.4.11, which requires 3:1 for the boundary of anything you can operate. Add --qz-rule-strong: #948EA6 (3.14:1) and move inputs, checkboxes and radios onto it; decorative separators stay on --qz-rule.

08

Phone & desktop

Two frames, exact sizes, and one fit rule.

The quiz is never a web page — it is a modal over someone's storefront or a block inside it. So the preview shows the container, not a browser window: simulating one invents space that will not exist and hides the only question a merchant has, which is whether it fits where they are putting it.

FrameWidthHeightClampTokensWhere the number comes from

Inline960700 560 – 780desktopAbove the 900 breakpoint, below the 1100 content cap. This is what Desktop shows.
Modal720620 520 – 680mobileThe launcher's own width. Declared, but NOT offered as a preview — see the note.
Tablet768920 720 – 1024mobileUnchanged. Still below 900, so still mobile tokens.
  • F1The phone is borderless and solid. No bezel, no chrome, no caption, 20px radius, opaque to all four edges. The device drawing was decoration around a number that was already doing the job.
  • F2Fit, never stretch. z = min(1, availW/w, availH/h), applied as transform: scale(), with the layout box set to the scaled size so the painted box and the layout box agree. Recomputed on resize and whenever the toggle flips. Never larger than life size.
  • F3The preview never leaves the screen. position: sticky with a dvh-based cap, so it stays visible while the editor column scrolls.
  • F4A borderless preview needs a ground it cannot match. The merchant's palette is theirs and can legitimately be pure white, so the stage behind it is recessed and the frame carries a soft elevation. Without both, a white-brand merchant sees nothing at all.
  • F5The zoom readout reads the applied --z. Never a hardcoded percentage — that is how it came to print “100%” over a preview painting at 92%.
The launcher modal is 720px wide and the runtime breakpoint is 900px. So a quiz opened from the floating launcher renders mobile tokens on a desktop machine, always. That is either deliberate or a bug nobody has looked at, but either way a “Desktop” toggle showing desktop tokens for a modal-mode quiz would be showing the merchant something their shoppers never see. Desktop therefore means the 960 × 700 inline band. The modal's geometry stays declared so a third preview mode is cheap to add — and it should be added, because a merchant embedding via the launcher currently cannot preview what ships.
09

Home

One page, two states. The composer is the anchor.

Before the first quiz: the composer, optically centred, nothing else. After it: the same composer, unchanged, with sections below. It never moves horizontally, resizes, or restyles between the two — that is what lets the page grow around it without reading as a different screen. The heading is the only thing that resizes, because 37px is a welcome on a blank page and the same 37px above a checklist is the page shouting over its own content.

Home is the one tinted page in the product (--qz-home-ground, #F5F4F8). The checklist is ordered by distance to revenue: a built-but-unpublished quiz earns nothing, a published-but-unreachable quiz earns nothing, captured emails with nowhere to go are being lost, and design is polish that cascades. All of it in ink — no alarm colour on the first screen after sign-in.

Live states

Found by auditing the code, not by imagining what might exist.

Every screen above is drawn at rest. These are the states the product actually enters and that nothing had a design for — each one was found by reading the code, and each cites the line that produces it. They are the difference between a spec that looks complete and one that is.

Two rules run through all of them. A failure that risks the merchant's work — a failed save, a blocked publish — never auto-dismisses and never fades; it persists until it is resolved, because the only copy of that work is the open tab. And every error names its way out: a retry, an escape, or a specific node to go fix. An error that only reports is an error the merchant cannot act on.

Autosave — four states, one chip

Saving…
Saving

isSaving. Appears only after the 700ms debounce fires, so typing never flickers the chip.

Saved
Saved

savedAt set. The only state any mock showed before this audit.

Not saved
Save failed

saveError. Never auto-dismiss and never fade — it persists until a retry succeeds, because the merchant's work is only in the tab.

Paused while AI edits
Paused

beginAiEdit(). Autosave is deliberately suspended so a debounced PUT cannot land a stale doc mid-call.

Generation — when it does not come back

This is taking longer than usual

Still working, but it has been over three minutes. You can wait, start again, or pick a template instead.

genStalled — 200s with no write during typing/templating. The escape is the retry-gen intent. Offer it; do not poll forever.

We could not draft this one

Nothing was lost — your goal is still here. Try again, or build it yourself.

Generation failed

Distinct from stalled: the job came back empty or errored. In production this is usually depleted AI credits, so the copy must not blame the merchant's input.

2026-08-09

Open — needs an owner call

The gold signature

The gold ◆ has five canonical moments today (wordmark, recommended template, decider question, loading mark, primary-CTA inline). Quartz has one accent and no gold. Either those five move to violet, or gold survives as a sixth colour and the one-accent rule is dead.Recommend: Move them to violet, drop the ◆ glyph.

22 sites
The pastel set

24 call sites plus 7 on the per-template palettes. These drive the four pastel stat cards and the category surfaces. Quartz replaces the stat cards with one tone and a big figure, but the category surfaces still need some way to differ.Recommend: Differentiate by shape and label, not hue — but this is a product call, not a CSS one.

31 sites
--qz-font-mono

Cannot be swapped blind. Sites that used mono for ALIGNMENT (counts, prices, ratios, IDs) need tabular-nums added; sites that used it as a LABEL style become Figtree 700 uppercase +.09em. Two different fixes, and someone has to look at all 35.Recommend: Split the list before touching any of it.

35 sites
The shopper progress bar

Five variants were built (Fraction, Endowed, Segments, Chapters, Countdown) and none is chosen. It appears on every question screen, so it is the last thing blocking a complete spec.Recommend: Chapters — it survives long labels and uneven question counts.

design call

What this fixes about today's UI

  • Removes the typewriter look: no monospace anywhere, figures are Figtree with tabular numerals so columns still align.
  • Gives control boundaries a token that actually meets 3:1 — today they are hairlines at 1.3:1.
  • Stops our accent competing with the merchant's brand inside the builder.
  • Makes every preview an exact, undistorted size that always fits and never leaves the screen.
  • Cuts the pill: 4/6/8 radii throughout, which is most of why the current admin reads younger than the product is.

Where it could bite

  • The four open decisions touch 88 call sites between them; none is a blind find-and-replace.
  • A merchant embedding via the floating launcher currently has no way to preview the modal — the geometry is declared but no toggle reaches it.
  • Dark mode is cut, not deferred. Reviving it needs a fresh contrast pass; it was never audited against the real call sites.
  • The shopper progress bar is unspecified, and it appears on every question screen.

Grounded in: WCAG 2.2 §1.4.3 contrast-minimum (4.5:1 body, 3:1 large) and §1.4.11 non-text contrast (3:1 for control boundaries) — every pair in section 03 is measured from the token values at build time, not eyeballed; NN/g on minimizing cognitive load and on progressive disclosure; and the working consensus across current product design systems that one spacing scale, one type ramp and a restrained accent are what make new screens feel native. Typefaces are open-licence (SIL OFL) and self-hosted, so nothing here depends on a font CDN.

01 · The model

Five surfaces, one spine

Every capability lives on exactly one of five surfaces. Nothing floats: the merchant sets a control, it autosaves to the one quiz document, the live preview re-renders it at the chosen device & pop-up size, and Publish bakes it into the storefront embed. That chain is the through-line for everything below.

BuildThe canvas

Screens, blocks, questions & answers, per-screen background. What's on each screen.

ProductsWhat it recommends

Catalog scope, buckets, and how each answer maps to products.

LogicHow it decides

Rules, branching, scoring, and the path tester.

DesignHow it looks

Brand tokens, structural presets, spacing, backgrounds — inherited from the store.

SettingsHow it behaves

Placement & size, discounts, capture, boosters, integrations, locales.

Set a control→ Autosaves to the quiz doc→ Preview re-renders (device · size)→ Publish bakes the embed→ Live on the store

Two more surfaces sit above these: Templates (start from a proven flow — pre-sets placement, gate, length, result), and the Preview toolbar (device toggle, pop-up size, Expand) which is a *view* of the committed settings, not a separate place to configure.

03 · The part that's subtle

Pop-up sizes: select the size, then adapt the content

Choosing a size is one control. Making the content look right at that size is a second set of controls — because a bigger frame must mean more breathing room, not stretched pictures. This is the piece worth getting exactly right.

Step 1 — Select the format & size

Placement is a real, committed setting (Settings → Placement), so the choice is locked in and baked at publish — there's no separate "save." The Preview toolbar mirrors the same setting so you can switch sizes while you watch.

Compact~460px. Email capture, 1–2 question micro-quizzes.
Standard~660px. The everyday centered card.
Large~920px. Summer-Fridays-style roomy modal.
Full-screenMeUndies-style takeover, thin margin.

Step 2 — Adapt the content to the size (so nothing stretches)

These controls decide how the quiz fills the chosen frame. They live mostly in Design (global) and on each image, and they respond to the frame width so a large modal reads as generous, not blown-up.

Content max-width

Inside a wide/full-screen modal, the reading column caps (e.g. ~640px for questions, ~1080px for a product grid) and centers. The frame gets bigger; the text column doesn't stretch to the edges. Design → Layout

Padding & gutters scale up

A Large / Full-screen modal uses larger section padding and side gutters than Compact. Merchant control is the Spacing feel (Compact ↔ Airy) plus per-screen padding; the size preset raises the floor automatically. Design → Style · Spacing

Images fit, never stretch — the key rule

Every image has a fixed aspect ratio (1:1 · 4:5 · 4:3 · 16:9) + fit (Cover crops to fill / Contain shows the whole image) + a draggable focal point. On a bigger frame the image renders larger at the same ratio, cropped by the focal point — it is never distorted. Product-grid ratio is one shared setting so cards always align. Per image · answer / hero / product

Columns respond to width

Answers: 1 column on mobile → 2–3 on desktop/large. Results: 1 → up to 4, capped. Merchant sets the desktop column target; mobile collapses automatically. Choice → Design · ColumnsResult → Columns

Type scale (bounded)

Headings/body step up modestly on wide frames and stop — a floor of 14px body, a ceiling so nothing balloons. Driven by the brand token scale, not per-size guesswork. Design → Brand · Type

The governing principle: the quiz is one responsive document. The size control changes the frame; Design tokens + per-image settings + column targets change how the content fills it. Layout is computed at the true frame width, then the whole thing is scaled to fit the builder pane — so the preview never lies about wrapping, and "more room" always means padding & larger images at a fixed ratio, never stretch. To complete: expose per-size padding as an explicit, previewable control (today it's the global Spacing feel).
